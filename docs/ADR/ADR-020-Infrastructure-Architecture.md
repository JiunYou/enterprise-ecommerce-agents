# ADR-020: Infrastructure Architecture & Persistence Strategy

## Status
Proposed

## Context
As we transition from the Application Layer (Phase 11) to the Infrastructure Layer (Phase 12), we need to define the technological stack and patterns used to implement the data persistence abstractions (`IOrderRepository`, `IInventoryRepository`, `IApplicationUnitOfWork`).

The Domain Models (`Order`, `InventoryItem`) have been designed with strict encapsulation (private constructors, private setters) and utilize Value Objects (e.g., `Money`, `StockQuantity`). Our persistence mechanism must map these structures to relational tables without compromising Domain purity.

Furthermore, Domain Events generated by aggregates must be reliably published. To prevent dual-write problems and distributed transaction overhead (2PC), we require an Eventual Consistency strategy.

## Decision
1. **Entity Framework Core (EF Core) & MySQL**
   - We will use EF Core with `Pomelo.EntityFrameworkCore.MySql` as the ORM and Database provider.
   - We will use the Fluent API exclusively for mapping Entities and Value Objects (Owned Types/Value Converters) to keep the Domain models devoid of ORM attributes.
2. **Repository Pattern**
   - `OrderRepository` and `InventoryRepository` will encapsulate `EnterpriseCommerceDbContext` and implement the Application interfaces.
3. **Unit of Work & Outbox Pattern**
   - `EnterpriseCommerceDbContext` will implement `IApplicationUnitOfWork`.
   - Before `SaveChangesAsync` commits the transaction to MySQL, it will intercept all Domain Events from tracked aggregates.
   - These events will be serialized and inserted into an `OutboxMessages` table within the same database transaction.
   - A separate background worker (Phase 13) will be responsible for relaying Outbox Messages to RabbitMQ.

## Consequences
### Positive
- Strict isolation of the Domain Model is maintained.
- MySQL handles ACID properties for state changes and event storing, preventing missed events.
- Easy to test utilizing Testcontainers or EF Core InMemory providers.

### Negative
- EF Core mappings for encapsulated models can be verbose and require reflection or mapping configurations.
- Requires building a background service for polling/pushing the Outbox.
